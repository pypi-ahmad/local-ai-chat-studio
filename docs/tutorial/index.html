02 · Product boundary

A private context workbench, not just a chat box.

The studio combines conversation, provider choice, evidence inspection, replay, reusable context, and memory in one local workspace.

1

Workspace

Chats, files, memories, presets, run records, receipts, policies, and profile data share one canonical SQLite store.

11

Provider paths

Local Ollama plus cloud, compatible, OpenRouter, and OpenCode routes use one normalized streaming interface.

5

Context gates

Memory, retrieval, attachments, web, and backpacks are separately permitted for each remote provider.

What it does well

  • Streams local or cloud model answers and lets you cancel an active run.
  • Preflights every conversational turn with a context budget, safety findings, sources, and confirmation requirements.
  • Supports files and provider-native images, with explicit selection per turn.
  • Branches conversations, compares models, replays runs, diffs answers, and exports full or redacted bundles.
  • Curates durable memory from a whole chat through a selected LLM, retaining source-message provenance.

What it is not

  • It is not a hosted multi-user service and has no user-account authentication layer.
  • A session cookie scopes browser credentials and run access; it is not identity or encryption.
  • “Local-first” does not mean every request stays local. Cloud providers, optional web search, and remote memory extraction transmit selected data.
  • The single-process design is appropriate for a trusted localhost, not horizontal scaling.

03 · Zero-to-hero foundations

The concepts the interface assumes.

LLM, model, token, and context window

A large language model predicts text from the input it receives. A provider hosts or exposes models. Tokens are the units counted against a context window. Instructions, recent history, retrieved evidence, files, memories, and generated output all compete for that finite space.

Temperature and reproducibility

Temperature controls sampling variation, not factual accuracy. Replaying the same request helps compare behavior, but remote models and nondeterministic sampling can still differ. The replay bundle preserves the request and context used by the studio.

Embeddings, vector search, and RAG

An embedding maps text to a vector. Similar vectors suggest related meaning. Retrieval-augmented generation (RAG) searches stored chunks and places the best evidence into the current request. It does not train the model or guarantee truth.

Memory versus conversation history

History is the ordered transcript. Memory is a curated set of durable facts, preferences, goals, constraints, decisions, and project context that can be reused across chats. This app stores memory in SQLite; Chroma is an optional search index.

REST, SSE, PKCE, and OAuth

REST routes create and read resources. Server-Sent Events (SSE) carry one-way run updates from server to browser. PKCE protects an authorization-code exchange. OAuth lets a provider authorize access without putting an account password into this app.

Local-first and data boundaries

Local-first means the application and canonical data run on your machine. It does not override your provider choice. The preflight plan and per-provider policy make remote transmission visible and controllable.

Plain-language modelYour prompt is a parcel. Context sources are optional inserts. Preflight shows the packing list before a remote courier receives it.
Technical modelTurnPreflight becomes a hash-bound ContextPlan; assemble_messages() then materializes only included, permitted, non-excluded sources.
Operating modelLocal inference exchanges cloud spend for local hardware and support. Cloud inference broadens model choice but introduces variable cost and data-processing dependencies.

05 · User manual

Operate the workspace with intent.

Chat

Conversations

Create, select, rename, pin, search, or delete a conversation. Search the provider-scoped model picker by name, ID, or capability and filter for Vision or Reasoning. Answers stream live; Stop cancels the active run.

Messages

Work from any point

Use previous/next controls and the position counter to navigate saved messages. Copy, rate, or branch at a chosen message without losing the original.

Context

Inspect before sending

The context rail shows used and available tokens, exact percentage, an 80% warning, and precise overflow. Use the optional persisted Context/Evidence inspector or open the full pages.

Files

Select per turn

Upload documents or images and follow their Uploading, Ready, or Failed cards. Failed uploads expose the server error plus Retry and Remove actions.

Focus

Hold one objective

Create a temporary focus contract with an objective, success criteria, and constraints. Use a context backpack for deliberate reusable facts or project rules.

Compare & Replay

Make differences visible

Send one prompt to two to four selected models in parallel, follow each independent stream, cancel all active runs together, replay a completed run, diff answers, or export a full local bundle and a redacted share bundle.

A first useful workflow

  1. Create a conversation and choose Ollama Local for an entirely local first run.
  2. Upload a small document. Select its checkbox beside the composer.
  3. Ask a question that can be answered from the document.
  4. Review the preflight budget and Evidence source. Confirm only if the plan matches your intent.
  5. After the answer, inspect Replay and export a redacted bundle to understand what is safe to share.

Memory workflow

Choose Save memories & close when a conversation contains durable information worth reusing. The selected model reduces the whole chat into short user-grounded points. A remote model requires confirmation before the transcript leaves the machine. Review new memories in Library; approve quarantined items, archive stale items, pin critical context, or delete mistakes.

Settings and recovery

Settings shows server/Ollama health and loaded models, manages the local profile, imports or exports JSONL, imports the old preview database with a backup, and exposes a confirmation-protected panic wipe. Stop Studio cancels active generations and stops the managed chat-studio process; Ollama and OpenCode keep running.

Good habitUse Evidence as your packing list and Replay as your receipt. If either looks surprising, stop before adding more provider access.
UI contractThe React client preflights first, submits the returned plan_hash, and streams retained events for the resulting run.
Adoption signalThe product is strongest where users need model choice plus visible context controls—not where a basic hosted chat is sufficient.

06 · Providers and authentication

One model picker, several trust paths.

PathAuthenticationBoundary
Ollama LocalNo keyLocal endpoint configured by CHAT_OLLAMA_HOST.
Ollama CloudBearer API keyRemote; separate from local Ollama.
OpenAI, Agnes AI, Gemini, xAI, OmniRouteSession key or environment fallbackRemote unless a compatible gateway is explicitly local.
AnthropicSession key, environment fallback, or workload identityRemote.
OpenRouterSession key, environment fallback, or PKCE sign-inRemote routing service.
OpenCode Zen / GoSession key or environment fallbackRemote OpenCode inference.
OpenCode BridgeOAuth methods reported by a local OpenCode serverThe bridge is loopback-only, but connected upstream models remain remote.

Credential precedence

A key entered in the browser wins for that session. Otherwise the provider-specific environment variable is used. Anthropic can additionally discover configured workload identity. Provider catalog failures are isolated so one unavailable service does not erase other model lists.

OpenCode OAuth bridge

Run OpenCode on loopback. The studio queries the server for available OAuth methods and shows only what it reports—such as ChatGPT, Claude, or SuperGrok when supported by that installation. The studio rejects non-loopback bridge URLs. Each generation uses an ephemeral OpenCode session with tools disabled.

Important distinction: a local OpenCode process is a bridge, not proof of local inference. Remote context policy still applies to the upstream provider.

Evidence: backend/app/sessions.py, backend/app/providers.py, provider routes in backend/app/main.py.

07 · Data and trust

Know what persists, what travels, and what is filtered.

Persists

SQLite

Conversations, messages, runs, events, receipts, memories, files metadata, presets, policies, focus sessions, and profile state live in data/app.db.

Optional index

Chroma

When CHAT_EMBED_MODEL is set, document and active-memory vectors live under data/chroma. SQLite remains canonical.

Ephemeral

Process memory

Browser-entered credentials and active async task objects vanish on restart. Run records and events themselves are persisted.

Preflight safety

  • Remote providers begin with prompt-only access; context classes are enabled per provider policy.
  • Likely secrets or personal information pause a send. You can confirm or redact and preflight again.
  • Retrieved instruction overrides are quarantined rather than silently becoming system instructions.
  • Selected attachment IDs must belong to the active conversation. Models that explicitly lack vision reject image input.
  • Redacted replay exports remove private context and image bytes.

Memory safety

The LLM proposes atomic memories, then consolidates them against existing items. Only statements tied to actual user-message IDs can be accepted. Secret/PII candidates are discarded; prompt-injection-like candidates are quarantined. Provenance records the source messages, extractor provider/model, and selection reason.

Network warning: web search sends the query to DuckDuckGo, and cloud memory extraction sends the full conversation to the chosen provider after confirmation.

08 · Product and operations guide

Evaluate the operating fit, not the demo glow.

Best-fit teams

Knowledge work with mixed sensitivity

Developers, analysts, researchers, and small teams that want local models for private work and cloud models for capability—without losing visibility into context.

Core differentiation

Context accountability

The value is not merely “many models.” It is preflight, source exclusion, replay, redaction, provenance, and explicit provider boundaries around those models.

Cost drivers

Hardware, tokens, and support

Local inference needs capable hardware and model operations. Cloud inference adds usage spend. The model picker shows source-linked standard rates, and preflight estimates input cost. Unknown gateways remain unpriced; estimates exclude output, caching, tools, media, discounts, taxes, and subscriptions.

Current maturity

Trusted localhost workspace

Suitable for individual use and controlled pilots. User authentication, multi-tenancy, centralized policy, audit administration, and horizontal scaling are not shipped.

Pilot scorecard

QuestionGood signalStop or redesign when
Do users need both local and cloud models?Workloads vary by sensitivity or capability.One approved hosted assistant already covers the need.
Does context provenance matter?Users must explain which files, memories, or searches influenced a result.Casual chat is the only workflow.
Can it remain on trusted localhost?Each pilot user runs a controlled workstation.A shared public service is required immediately.
Can provider policy be owned?A named owner approves models, keys, and context classes.Users may connect arbitrary services without governance.
Can outputs remain advisory?Humans review evidence and make decisions.Unattended consequential automation is required.

Recommended pilot

  1. Select one bounded workflow and define a human-reviewed success measure.
  2. Start with Ollama Local and a small set of approved documents.
  3. Add one cloud provider with prompt-only policy; expand context permissions deliberately.
  4. Review evidence, replay bundles, failure cases, latency, and cloud spend weekly.
  5. Decide whether the missing multi-user controls require product work before broader adoption.
Decision summaryAdopt for controlled individual workflows that benefit from context transparency. Do not position the current build as an enterprise collaboration platform.

09 · Architecture

Trace the packet through the system.

Signature instrument

Context packet rail

Core invariants

  • Pydantic contracts are the backend API source of truth; OpenAPI generates frontend TypeScript types.
  • The plan hash binds a user confirmation to the context that was actually reviewed.
  • SQLite is canonical. Chroma accelerates semantic retrieval but can be rebuilt.
  • Provider-specific behavior stops at the adapter boundary; runs consume normalized messages and yield text deltas.
  • The active task registry is process-local, while run snapshots and events are durable.
Mental modelThe browser asks, FastAPI checks the packing list, a provider answers, and SQLite keeps the receipt.
Composition rootcreate_app() owns one Store, SessionVault, ProviderRegistry, and RunManager; middleware adds the session cookie and security headers.
Scaling implicationThe local task and credential state make this intentionally single-process. A shared service would need external identity, session state, events, and policy administration.

11 · Technical deep dives

The five flows most worth understanding.

1. Context preflight and confirmation
  1. The frontend creates a TurnPreflight with prompt, model, options, and selected attachment IDs.
  2. The backend validates attachment ownership and known vision support.
  3. build_context_plan() applies provider policy, scans text and sources, estimates tokens, and prunes lower-priority context.
  4. The returned plan includes a hash, findings, sources, sections, and confirmation flag.
  5. Submission repeats or reconstructs the plan. A changed hash returns a conflict instead of sending different context.
2. Streaming and durable runs
  1. RunManager.create() writes a queued run and starts a strongly referenced async task.
  2. The adapter yields text deltas. Each event updates the in-memory subscriber state and SQLite record.
  3. SSE subscribers receive retained events first, then wait for new ones.
  4. Completion appends the assistant message and a hash-chained receipt. Cancellation closes the provider stream cooperatively.
3. Files and images
  1. Upload bytes are decoded and validated before persistence.
  2. Documents become local text; large material can be chunked for retrieval.
  3. Images are verified with Pillow and retain data bytes for provider-native vision input.
  4. Only IDs selected for the current turn enter its plan, and remote attachment policy can still exclude them.
4. LLM-curated memory
  1. The full transcript is labeled with message IDs and split into bounded chunks.
  2. The active provider proposes durable user-grounded memories.
  3. A second model pass consolidates candidates against existing memory.
  4. Code accepts only valid user source IDs, allowed dispositions, bounded content, and nonduplicates.
  5. Safety filtering discards secrets/PII, quarantines injection-like text, atomically stores the batch, then optionally syncs active items to Chroma.
5. Provider and OAuth boundaries
  1. The registry discovers provider models concurrently and caches descriptors.
  2. Session keys override environment fallbacks without persistent secret storage.
  3. OpenRouter uses a session-bound PKCE verifier with expiry.
  4. OpenCode calls only an HTTP loopback server, uses reported OAuth methods, disables tools, and deletes its ephemeral upstream session.

12 · Build, test, contribute

Extend the narrowest responsible layer.

Lab A

Add a provider

  1. Add its session/environment mapping.
  2. Implement the normalized adapter.
  3. Register it once.
  4. Test discovery, streaming, auth metadata, images, and safe failures.

Lab B

Add an API workflow

  1. Define Pydantic contracts.
  2. Add storage only if state must persist.
  3. Implement the route and contract tests.
  4. Regenerate OpenAPI types.
  5. Add the typed client and UI test.

Lab C

Add a file type

  1. Declare the accepted extension.
  2. Validate bytes before parsing.
  3. Return plain text or a verified image.
  4. Test valid, empty, mismatched, and malformed files.

Lab D

Add context

  1. Give the source provenance and trust metadata.
  2. Apply provider policy before inclusion.
  3. Budget and prune it deterministically.
  4. Bind it to the plan hash and replay bundle.

Testing architecture

Backend tests use FastAPI TestClient, in-memory SQLite, deterministic adapters, and the echo provider. Frontend tests use Vitest, Testing Library, jest-dom, and jsdom. Real providers, OAuth, Ollama hardware behavior, and browser end-to-end flows remain manual smoke tests.

Contribution rule: regenerate frontend/src/api/schema.ts after contract changes, preserve unrelated work, and keep provider, run, store, and context edits covered by focused lifecycle tests.

13 · Troubleshooting and reference

When something fails, start at the boundary.

SymptomFirst checks
No models appearStart Ollama or connect the provider credential, then reload discovery. One provider can fail independently.
Ollama is offlineRun ollama serve; verify CHAT_OLLAMA_HOST and the local model catalog.
Image rejectedConfirm the file is a real supported image and the selected model reports vision capability.
File not includedSelect its checkbox for this turn and allow attachments in the provider policy.

Glossary

Adapter
A provider-specific implementation behind the studio’s normalized model and streaming contract.
Backpack
A deliberate reusable packet of facts or constraints attached to context.
BYOK
Bring your own key: use a provider credential controlled by the user.
Context plan
The inspectable, budgeted set of sections, sources, and findings prepared before a turn.
Embedding
A numeric representation used to search for semantically related text.
PKCE
A one-time verifier mechanism protecting an OAuth authorization-code exchange.
Provenance
Metadata showing where context or a memory came from.
RAG
Retrieval-augmented generation: adding relevant stored evidence to a request.
SSE
Server-Sent Events, the one-way stream used for run updates.
